# 错误处理参考

> 自有模型服务尚未上线。本文地址及模型名称为占位示意，不是现有在线体验的调用协议；正式版本以上线公告为准。

以下是客户端收到状态后的处理方式，不代表全部状态均已在生产环境实测。错误体可能为 JSON、HTML、文本或空；后端统一错误结构尚未确认，不定义虚构的 error.code。

| 状态 | 客户端分类 | 处理建议 |
| --- | --- | --- |
| 400 / 422 | rejected | 修正输入：核对目标列、字段类型和 null。 |
| 413 | payload-too-large | 减少请求大小：核对网关 JSON 上限；不等同于 CSV 的 1 MiB 限制。 |
| 429 | rate-limited | 等待再试：若有 Retry-After 可参考；当前网页不自动重试。 |
| 408 / 504 | timeout | 检查服务状态：区分网关超时与客户端主动取消。 |
| 其他非 2xx 状态 | unavailable | 检查接入环境：确认权限、路由和上游状态；并非固定认证方案。 |
| 2xx + JSON／结构无效 | invalid-response | 检查原始响应：核对模型名、索引、数组长度及概率。 |
| 网络连接失败 | unavailable | 检查连接：检查网络、DNS、TLS 和代理；保存状态与错误摘要。 |

网页运行使用 120 秒计时器；JavaScript 示例用 AbortSignal.timeout(120_000)，cURL 用 --max-time 120，Python 的 timeout=120 是 socket 操作超时，不是严格总时限。它们都不是服务 SLA。取消等待不代表后端任务已停止。

输入错误先修正再重试。网络或服务错误应先确认原请求状态，再手动重试；自动集成可考虑有上限的退避，幂等性、重复计费和取消机制尚未确认。
